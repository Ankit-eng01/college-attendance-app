Privacy & Security Policy
1. No Advertising or Analytics Trackers Attendify ships without analytics SDKs, advertising pixels, or third-party cookies. We do not sell personal or academic data.
2. Local Storage vs. Cloud Backup Stored locally (this browser): Subjects, attendance logs, calendar entries, theme/target preferences, your Sync Code, and your Private Secret Key are stored in browser localStorage so Attendify works offline.
Uploaded to the cloud: Once you add at least one subject while online, both Guest Mode and Account Mode automatically send your attendance data, student name, theme/target preferences, compact device profile (type, browser, OS, screen size), and account email (if signed in) over HTTPS to the Attendify Sync API. Passwords are never saved locally and are only sent over HTTPS during sign-up or sign-in.
3. Guest Mode, Accounts & How Sync Codes Work Guest Mode: Requires no email or password. Attendify auto-generates a Sync Code (ATN-...) and Private Secret Key in your browser and uses them to back up automatically over HTTPS once subjects exist. Guest Mode has no email/password recovery if you lose both this device and your pairing credentials.
Account Mode: Signing up stores a salted scrypt password hash on the server and seals your pairing Secret Key with AES-256-GCM so signing in on another device restores your Sync Code + Secret Key.
How Sync Codes work: Your Sync Code identifies your cloud record; your Private Secret Key authorizes reads, updates, and server deletion (verified server-side against its SHA-256 hash). Traffic is encrypted in transit via HTTPS, while attendance JSON payloads on the server are not client-side end-to-end encrypted—keep your Secret Key and pairing token (Code:Key) private.
4. XSS Protection & Strict Content Security Policy (CSP) All rendered user inputs undergo strict character escaping. A Content Security Policy restricts scripts to first-party sources and blocks unauthorized payloads and cross-site scripting.
5. Verified JSON Backups & Schema Validation Imported backup files are checked by an in-memory schema validator that verifies object bounds, property types, and value limits before applying state changes.
6. Your Data Rights & Deletion You can export a CSV or JSON backup at any time. Using "Wipe cloud backup from server" in Settings deletes only the remote server copy while keeping local records. Using "Clear all subjects & data deletion options" erases local browser storage and deletes your server backup for both Guest and Account modes.
